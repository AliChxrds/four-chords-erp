## Working rhythm

1. Read this dashboard and the current weekly plan at session start. Inspect existing changes before editing.
2. Pick one Ready task and move it to In progress. Continue with ERP-004; gather ERP-001 business answers alongside independent technical work.
3. Move implemented work to Testing. Mark Done only after its acceptance criteria pass and evidence is recorded.
4. At session end update task status, progress, decisions, and next action. Record actual developer hours only when reported.
5. At the weekly review demonstrate working results, compare actual progress with estimates, and explicitly revise scope or dates.

States: Backlog → Ready → In progress → Testing → Done. Use Blocked with a named dependency and unblock action. Keep one main implementation task In progress.

These documents are updated during work sessions; they do not provide automatic monitoring. Initial pack creation does not complete the implementation tasks.

## Definition of done

The relevant workflow works through the interface, API, and database, or satisfies a backend-only task's technical criteria. Permissions, validation, and expected failures are addressed where applicable. Relevant checks pass and results are recorded. Financial and stock features require integration checks. Documentation matches behavior, and no critical defect remains in delivered scope.
